## Context

本計画自体が `.plans/20260813-2333-build-qtk-tool/` のような 7 ファイル構成で管理されていた。計画ドキュメントのライフサイクル (ドラフト中・実行中・完了・置き換え) が機械的に判定できず、issue/ADR との紐付けもない状態だった。

一方で、wayfinder スキルの「マップ」を milestone 種別で管理する構想があったが、milestone は本質的に issue のグループ化であり、plan (計画ドキュメント) と機能が重複する。

## Decision

**plan 種別を追加**し、**milestone 種別は削除**する。

- **plan 種別**: 計画ドキュメントの作成・一覧・編集・アーカイブを CLI で管理。本文テンプレートは既存の 7 ファイル構成 (Context/Goals/Design/Tasks/Risks/References) を 1 ファイルに統合
- **plan_status**: `drafting` → `ready` → `in-progress` → `completed` / `abandoned` / `superseded` (issue の `status` と区別するため `plan_status` を使用)
- **related_issues / related_adrs**: plan から issue/ADR への構造的紐付け
- **supersedes / superseded_by**: plan の置き換え関係の追跡
- **wayfinder のマップ**: plan (計画全体) + issue (子チケット、`--dep` で計画 issue に依存) の組み合わせで代替。milestone は使用しない

## Consequences

**ポジティブ**:
- 計画ドキュメントのライフサイクルが CLI で管理可能
- plan と issue/ADR の構造的紐付け (related_issues / related_adrs)
- 置き換え関係の自動更新 (supersedes 指定時、旧 plan の superseded_by と status を自動更新)
- wayfinder 統合が plan + issue でシンプルに実現

**ネガティブ**:
- 長大な計画を 1 ファイルに統合するため可読性が低下する可能性 (R07)。緩和策として `plan show --section tasks` 等の将来追加を想定
- 既存 `.plans/` の自動移行機能は提供しない (手動で `qtk plan create` → 本文を貼り付け)

**リスク**:
- plan の本文が数百行になる可能性。セクション表示機能 (Issue #0009) で緩和
