## Context

ローカル課題管理ツールのストア方式として、Beads は Dolt DB を採用している。しかし Dolt DB はバイナリファイルであり、git diff で履歴が読めず「ファイルを直接読む」文化に不適合だった。ユーザーは Markdown ファイルを git で管理する文化を維持したいと考えていた。

## Decision

全データを **YAML frontmatter 付き Markdown ファイル** で保存する。DB (Dolt / SQLite) や JSONL は採用しない。

採用理由:
- **git でバージョン管理可能** — バイナリファイルと違いテキストベースで diff が読める
- **人間が直接ファイルを開いて読める** — エディタでそのまま閲覧・編集できる
- **Backlog.md 方式の利点を継承** — Markdown 文化を活かしつつ CLI で構造化操作を提供

却下した代替案:
- **Dolt DB (Beads 方式)** — git diff で履歴が見えない。「ファイルを直接読む」文化に不適合
- **SQLite** — git でバージョン管理できない (バイナリファイル)
- **JSONL ファイル** — Markdown ほど人間が読みやすくない。本文 (Context/Decision 等) の可読性が落ちる

## Consequences

**ポジティブ**:
- git で履歴管理が可能。PR レビューで変更内容が一目で分かる
- 人間がエディタで直接読み書きできる (CLI が壊れてもデータは生き残る)
- 既存の Markdown 運用文化との親和性が高い

**ネガティブ**:
- 全文検索のパフォーマンスが DB に劣る (ファイル全体をスキャンする必要がある)
- 複雑なクエリ (JOIN 等) ができない (アプリケーション層で実装する必要がある)
- 大量データ (数千件以上) では一覧表示が遅くなる可能性

**リスク**:
- データ量増大時のパフォーマンス低下。緩和策としてインデックスファイル (`.qtk/index.json` 等) の将来追加を想定
