## Context (背景・現状・制約)

### 背景・動機

`qtk web` サブコマンド（ローカル Web UI / Kanban）に2つのバグがある。ユーザーが `bunx @masinc/qtk@latest web` を実行すると以下が発生する:

1. **404 Not Found** — `http://127.0.0.1:3000` を開いても index.html が返らず 404 になる
2. **ポート 3000 の競合リスク** — ポート番号が 3000 に固定されており、Vite / Next dev / Rails / Bun.serve デフォルトなど多数の開発サーバーと競合する。使用中の場合はフォールバック処理がなく起動時例外になる

これらは npm 経由（ビルド済み `dist/cli.js`）で実行した場合に顕在化するリリース阻害バグであり、公開済みパッケージの利用体験を著しく損ねる。

### 現状

#### 静的ファイル配置とパス解決

- 静的ファイルは `src/web/static/index.html` のみ（385行、インライン CSS/JS 埋め込みの単一 HTML、フロントエンドビルド不要）
- `src/commands/web.ts:7` で `STATIC_DIR` を以下のように解決している:
  ```ts
  const STATIC_DIR = join(import.meta.dir, "..", "web", "static");
  ```
- **dev 実行** (`bun run cli.ts`): `import.meta.dir` = `src/commands/` → `src/commands/../web/static` = `src/web/static` 正しい
- **ビルド済み** (`dist/cli.js` 経由): `import.meta.dir` = `dist/` → `dist/../web/static` = `web/static`（リポジトリルート）存在しない
- `bun build` は静的ファイルをバンドルに含めないため、`dist/cli.js` 経由では index.html が見つからず 404 になる
- 現在 `dist/` 配下は `dist/cli.js` のみ（`dist/web/` は存在しない）

#### ポート番号

- `src/commands/web.ts:17`: `const port = options.port ?? 3000;` で 3000 固定
- `src/cli-main.ts:552`: ヘルプ文言「ポート番号 (デフォルト 3000)」
- 起動後メッセージ (`src/commands/web.ts:45`) は既に `server.port` を使って動的表示
- Bun.serve は `port: 0` を渡すと OS が空きポートを割り当て、起動後に `server.port` で実際のポートを取得できる（公式ドキュメント確認済み）

#### ビルドスクリプト・パッケージ構成

- `package.json` の `scripts.build`: `bun build cli.ts --outdir dist --target bun`（コピー処理なし）
- `package.json` の `scripts.prepublishOnly`: `bun test && bun run typecheck && bun run build`
- `package.json` の `files`: `["dist/", "src/", "README.md", "LICENSE", "CHANGELOG.md"]`
- `package.json` の `bin`: `{ "qtk": "dist/cli.js" }`
- `scripts/` ディレクトリは存在しない
- ランタイム: Bun 1.3.14（Windows）

## Design (設計方針・アーキテクチャ・データモデル)

### How

#### 修正1: 404 修正 — ファイル存在確認フォールバック + ビルド時コピー

パス解決は `existsSync` で候補を順に試す方式を採用（`config.ts:21-29` の `findStoreDir` と同じ慣行）:

```ts
// src/commands/web.ts (変更後)
const STATIC_DIR_CANDIDATES = [
  join(import.meta.dir, "web", "static"),        // ビルド済み: dist/web/static
  join(import.meta.dir, "..", "web", "static"),  // dev: src/commands/../web/static = src/web/static
];
const STATIC_DIR =
  STATIC_DIR_CANDIDATES.find((d) => existsSync(d)) ?? STATIC_DIR_CANDIDATES[0];
```

これにより:
- **ビルド済み** (`dist/cli.js`): 候補1 `dist/web/static` が存在（ビルド時コピーで作成）→ 採用
- **dev** (`bun run cli.ts`): 候補1 `src/commands/web/static` は存在しない → 候補2 `src/web/static` が存在 → 採用
- **npm グローバル** (`bunx`): 候補1 が存在（files に含まれている前提）→ 採用

ビルド時コピーは Bun スクリプトで行う（cross-platform 対応。シェルの `cp` は Windows で使えないため）:

```ts
// scripts/copy-static.ts (新規)
import { copyFileSync, mkdirSync, readdirSync } from "node:fs";
import { join } from "node:path";

const SRC = join(import.meta.dir, "..", "src", "web", "static");
const DEST = join(import.meta.dir, "..", "dist", "web", "static");

mkdirSync(DEST, { recursive: true });
let count = 0;
for (const file of readdirSync(SRC)) {
  copyFileSync(join(SRC, file), join(DEST, file));
  count++;
}
console.log(`Copied ${count} static file(s) to ${DEST}`);
```

#### 修正2: ポート自動割り当て

`src/commands/web.ts:17` の `?? 3000` を `?? 0` に変更するだけ。Bun.serve は `port: 0` で OS に空きポート割り当てを委譲し、`server.port` で実際のポートを取得できる。起動後メッセージ (`web.ts:45`) は既に `server.port` を使っているため変更不要。

### 代替案と却下理由

#### パス解決の代替案

- **(B) 実行モード判定（`Bun.main` / 環境変数）** — 却下。npm 経由 / ローカル / ビルド済み / テスト など複数パターンで判定ロジックが脆く、環境変数の設定漏れでバグ再発リスクがある
- **(C) ビルド時コピー + 条件分岐** — 却下。条件分岐が必須になり (A) の下位互換
- **(D) index.html を JS モジュールとして import し文字列バンドル** — 却下。385行のインライン HTML を template literal で持つとバッククォートエスケープ問題やメンテナンス性低下が生じる

#### ポート番号の代替案

- **3000 以外の固定デフォルト（例: 8787）** — 却下。固定値ならいずれも競合リスクが残る。空きポート自動割り当てが根本解決
- **使用中なら +1 ずつインクリメント探索** — 却下。Bun.serve の `port: 0` が OS レベルで効率的に空きポートを割り当てるため、自前探索は不要で信頼性も劣る

## Risks (リスク・懸念・緩和策)

1. **ビルド時コピーの失敗が検知されないリスク** — 影響度: 中 / 発生確率: 低
   - 緩和策: `copy-static.ts` 内で `readdirSync(SRC)` が失敗した場合は例外がスローされ `&&` 後続が止まる設計。T10 で `dist/web/static/index.html` の存在確認を必須ステップに含める

2. **existsSync フォールバックの順序依存** — 影響度: 中 / 発生確率: 低
   - 緩和策: 候補順序は「ビルド済みパスを先、dev パスを後」。両者は異なるディレクトリ階層に存在するため実質的に衝突しない。T10 で dev/ビルド済み両方を検証

3. **index.html 以外の静的ファイル追加時の漏れ** — 影響度: 低 / 発生確率: 低
   - 緩和策: `copy-static.ts` は `readdirSync` で全ファイルコピーするので漏れない。`contentType` 関数の拡張は本プランのスコープ外

4. **`files` への追記が npm の重複エントリで問題になるか** — 影響度: 低 / 発生確率: 極低
   - 緩和策: npm は重複エントリを許容する。T10 の `npm pack --dry-run` で確認

5. **ポート 0 の挙動が Bun のバージョン依存** — 影響度: 低 / 発生確率: 極低
   - 緩和策: 現行 Bun (1.3.14) で公式ドキュメント確認済み
