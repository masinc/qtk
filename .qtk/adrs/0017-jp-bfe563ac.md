## Context

qtk プロジェクトの `skills/` ディレクトリに、Matt Pocock のエンジニアリングスキル群の qtk CLI 統合版 (implement, setup-matt-pocock-skills, to-spec, to-tickets, triage, wayfinder) と qtk スキル (包括的ガイド) を配置していた。一方で、`masinc/skills` リポジトリでこれらのスキルのオリジナル版 (GitHub/.scratch 選択肢) を配布していた。

これにより以下の問題があった:

1. **重複**: 6個のスキルが `qtk/skills/` (qtk CLI 統合版) と `masinc/skills` (オリジナル版) の2箇所に存在
2. **保守負担**: スキルの変更を2箇所で行う必要がある
3. **配布の一元化**: `npx skills add` でインストールされるのは `masinc/skills` 側のみで、`qtk/skills/` の内容は配布されない
4. **アップストリーム同期**: `masinc/skills` 側は `mattpocock/skills` からの同期対象だが、`qtk/skills/` 側は同期フロー外

## Decision

全てのスキルを `masinc/skills` リポジトリに統合する:

1. **6個のスキルの qtk CLI 統合版を `masinc/skills` に上書き**: `mattpocock/engineering/` 配下の implement, setup-matt-pocock-skills, to-spec, to-tickets, triage, wayfinder に qtk CLI 選択肢を統合
2. **`qtk` スキルを自作スキルとして配置**: `masinc/skills/skills/masinc/qtk/` に配置
3. **`qtk/skills/` ディレクトリを完全削除**: プロジェクト固有のスキル配置を廃止
4. **アップストリーム同期のカスタマイズ記録**: `.upstream/mattpocock.md` に qtk CLI 統合の記録を追記
5. **`adr` スキルの削除**: qtk CLI の `adr` サブコマンドで完全置換されたため廃止

## Consequences

**ポジティブ**:
- スキルの単一配布元 (`masinc/skills`) に集約
- `npx skills add` で全プロジェクトに qtk CLI 統合版スキルが配布される
- 保守負担が半減 (1箇所のみ)
- アップストリーム同期フロー内で qtk CLI カスタマイズを管理可能

**ネガティブ**:
- qtk 未導入プロジェクトでも qtk CLI 選択肢が表示される (ただし選ばなければ影響なし)
- `mattpocock/skills` のアップストリーム同期時にコンフリクトの可能性がある (カスタマイズ記録で対応)

**リスク**:
- アップストリーム同期時に qtk CLI 統合部分が失われる可能性 → `.upstream/mattpocock.md` のカスタマイズ記録で同期時に要確認
