## Context

Backlog.md は `labels` フィールドを使用する一方、現行 Python 製 ADR CLI は `tags` を使用していた。issue と ADR でタグフィールド名が異なると混在が生じ、統一的なクエリやフィルタが困難になる。

## Decision

全種別 (issue / adr / spec / plan) で **`tags`** フィールドに一本化する。`labels` は使用しない。

- フィールド名: frontmatter の `tags` (配列)
- コマンド: `qtk tags` (一覧)、`qtk issue edit --tag` / `--add-tag` / `--remove-tag` / `--clear-tags`
- `qtk labels` コマンドは存在しない

却下した代替案:
- **`labels` (Backlog.md 互換)** — ADR では既に `tags` を使用しており混在する。全種別で統一するため `tags` に一本化

## Consequences

**ポジティブ**:
- 全種別で統一されたタグ操作 (`--tag` / `--add-tag` / `--remove-tag`)
- 横断検索 (`qtk search --tag`) が全種別で一貫動作
- `qtk tags` コマンドで全種別のタグを一覧可能

**ネガティブ**:
- Backlog.md からの移行時に `labels` → `tags` の変換が必要
- Backlog.md 互換を求めるユーザーには違和感がある可能性
