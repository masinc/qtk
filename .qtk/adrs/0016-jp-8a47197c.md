## Context

qtk CLI の初期実装では、ストアディレクトリを `qtk/` として配置していた。これには以下の問題があった:

1. **可視性**: `qtk/` は通常ディレクトリとして表示され、プロジェクトルートが煩雑になる
2. **名前衝突**: 内部管理ディレクトリを `.qtk/` としていたが、ストアディレクトリを `.qtk/` にリネームすると名前衝突が発生する
3. **設定ファイルの拡張子**: `config.yml` は YAML の標準拡張子 (`config.yaml`) と異なっていた
4. **バージョン管理**: `counter.lock` や `claim.lock` などのロックファイルが git に混入する可能性があった

## Decision

以下のリネームと機能追加を行う:

1. **ストアディレクトリ**: `qtk/` → `.qtk/` (隠蔽化)
   - ドットプレフィックスでディレクトリを隠し、プロジェクトルートをすっきりさせる
2. **設定ファイル**: `config.yml` → `config.yaml`
   - YAML 標準の `.yaml` 拡張子に統一
3. **内部管理ディレクトリ**: `.qtk/` → `.meta/`
   - ストアディレクトリ `.qtk/` との名前衝突を回避
   - `.qtk/.meta/` に `counter.json`、`counter.lock`、`claim.lock` を配置
4. **`.gitignore` 自動生成**: `init` 時に `.qtk/.gitignore` を自動生成
   - 内容: `*.lock` (ロックファイルのみ除外)
   - `counter.json` はバージョン管理対象 (clone 後も採番が引き継がれる)
   - 既存の場合はスキップ

## Consequences

**ポジティブ**:
- プロジェクトルートがすっきりする (`.qtk/` で隠蔽)
- 名前衝突が解消される (`.qtk/` と `.meta/` で役割分離)
- YAML 標準拡張子に準拠
- ロックファイルが git に混入しない (`init` 時に自動設定)
- `counter.json` は管理対象のため、clone 後も採番が引き継がれる

**ネガティブ**:
- 既存ユーザーは移行が必要 (`qtk/` → `.qtk/`、`config.yml` → `config.yaml`、`.qtk/` → `.meta/`)
- ただし `git mv` で機械的に移行可能

**リスク**:
- `init` 時の `.gitignore` 自動生成は既存ファイルをスキップするため、ユーザーが手動で `*.lock` を除外していない場合はロックファイルが混入する可能性がある
