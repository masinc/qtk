## 何をするスキルか

`setup-matt-pocock-skills` は、1つのリポジトリに関する3つの質問 — イシューがどこに住むか、トリアージラベルが何と呼ばれるか、ドメイン文書がどこにあるか — に答え、答えを `docs/agents/` の下の markdown ファイルとして記録します。

それらのファイルが、リポジトリ間で異なる唯一のものです。スキル自体はどこでも同一で、実行時に `docs/agents/issue-tracker.md` を読み、それが言うことをします。そのため、セットが GitHub に縛られない理由であり、スキルファイルをどこかに指すために編集する必要が決してない理由です。「スキルをカスタムイシュートラッカーにリンクする」で起動すると、プログラム的に接続できるものなら何でも、スキルへの変更ゼロで機能します。

これは決定的なスクリプトではなく、プロンプト駆動のスキルです。`git remote`、既存の `CLAUDE.md`、既存の `CONTEXT.md` を読み、見つけたものを提案し、何かを書く前にあなたの確認を待ちます。

## いつ使うか

`/setup-matt-pocock-skills` と入力して起動します — [エージェント](https://www.aihero.dev/ai-coding-dictionary/agent)は自分からは使いません。意図的に非起動可能とマークされているので、他のスキルもあなたのために発火できません。

他のエンジニアリングスキルを最初に使う前に、リポジトリごとに一度使います。[triage](https://aihero.dev/skills-triage)、[to-spec](https://aihero.dev/skills-to-spec)、[to-tickets](https://aihero.dev/skills-to-tickets)、または [wayfinder](https://aihero.dev/skills-wayfinder) がイシューの行き先を推測し始めたり、トラッカーにないラベルを適用し始めたりしたら、ここでまだセットアップされていません。プロジェクトの途中のリポジトリは実行するのに最適な場所です。スキルはすでにあるものを読み、以前の作業は無駄になりません。

## 前提条件

実行するリポジトリに書き込みます:

| 書くもの | 場所 |
| --- | --- |
| `issue-tracker.md` | `docs/agents/` |
| `domain.md` | `docs/agents/` |
| `triage-labels.md` | `docs/agents/`、`triage` スキルがインストールされている場合のみ |
| `## Agent skills` ブロック | すでに存在する `CLAUDE.md` / `AGENTS.md` のどちらか |

すべてコミットされる markdown です。ユーザーレベルやグローバルモードはありません: 設定はリポジトリに住むので、すべてのリポジトリが自分のコピーを得ます。

## 3つの決定

各セクションを推奨答えで導き、すでに確定した探索はスキップします。ほとんどの実行は2回の確認で終わりです。

| 決定 | 提案するもの | 実際に尋ねるタイミング |
| --- | --- | --- |
| **イシュートラッカー** | `git remote` に一致するもの | 常に — これが唯一の本当の選択 |
| **トリアージラベル** | 5つの正規名を保持(`needs-triage`、`needs-info`、`ready-for-agent`、`ready-for-human`、`wontfix`) | `triage` スキルがインストールされている場合のみ |
| **ドメイン文書** | シングルコンテキスト: ルートに1つの `CONTEXT.md` と `docs/adr/` | モノレポシグナルを見つけた場合のみ、そしてマルチコンテキストの `CONTEXT-MAP.md` を提供 |

トラッカーの選択肢:

| 選択肢 | イシューの場所 | 必要なもの |
| --- | --- | --- |
| **GitHub** | リポジトリの GitHub Issues | `gh` CLI |
| **GitLab** | リポジトリの GitLab Issues | `glab` CLI |
| **ローカル markdown** | このリポジトリの `.scratch/<feature>/` の下のファイル | 何もない — リモートがまったくない |
| **その他** | あなたが言うところ | ワークフローを説明するあなたからの1段落 |

最初の3つはスキルのテンプレートとして出荷され、箱から出して機能します。ローカル markdown はフォールバックではなくファーストクラスの選択肢です: リモートのないソロプロジェクトは完全にサポートされます。繰り返す価値のある1つの注意: GitHub を使っているならローカル markdown を使わないでください。それらは選択肢であり、レイヤーではありません。

「その他」もスタブではありません。Jira、Linear、Azure DevOps、Beads がすべて機能する理由です: ワークフローを説明し、スキルがあなたの散文を `docs/agents/issue-tracker.md` に記録し、下流のスキルが散文に従います。コミュニティはすでにこれをやっています — [MCP](https://www.aihero.dev/ai-coding-dictionary/mcp) 上の Jira バリアント、`gh` の形をした Gitea CLI、手作りのローカルダッシュボード。

## よくある質問

**GitHub を使わなければならない?**

いいえ。GitHub、GitLab、`.scratch/` の下のローカル markdown はすべて既製テンプレートとして出荷され、他のものは「その他」パスを通じて機能します。これは記録上最も繰り返される質問で、おおよそ次の言葉です: *「hard locked to github」*、*「can I use GitLab / Jira」*、*「what about Azure DevOps」*。答えは毎回、トラッカーはセットアップの答えであってスキルの特性ではないということです。

**スキルを更新した後に再実行する必要がある?**

v1.1 の直後に直接尋ねられ、Matt はイエスと言いました。スキル自身の閉じメッセージはより柔らかく、トラッカーを切り替えるか最初からやり直す場合にのみ再実行が必要と言います。両方とも弁護可能で、ギャップの理由は現実です: シードテンプレートはバージョン間で変わるので、古いリリースによって書かれた `docs/agents/issue-tracker.md` は、今それを読んでいるスキルに対して古くなることがあります。下流のスキルがドキュメントが異なって説明していることをやり始めたら、再実行が安い修正です。

**`CLAUDE.md` に書いたが、私は Codex を使っている。**

既知のギャップで、まだオープンです。ファイル選択ルールは「`CLAUDE.md` が存在すればそれを編集し、そうでなければ `AGENTS.md`」です — 実行中の[ハーネス](https://www.aihero.dev/ai-coding-dictionary/harness)ではなく、どのファイルが存在するかをチェックします。Claude Code から残った `CLAUDE.md` があるリポジトリは、Codex が決して読まない場所に `## Agent skills` ブロックを得ます。2つの回避策が流通しています: ブロックを手で `AGENTS.md` に移動するか、`AGENTS.md` を正規にして `CLAUDE.md` をそれを指す1行のポインタにするか。どちらのファイルも存在しなければ、スキルは選ぶのではなくどれを作るか尋ねます。それは、ただ決めることを期待した人々を混乱させました。

**トリアージラベルを作成しなかった。**

作成しません。`docs/agents/triage-labels.md` は*マッピング*です — トラッカーのどの文字列が5つの正規ロールに対応するかを `/triage` に伝えます。`gh label create` を実行しません。新しい GitHub リポジトリではラベルは本当にまだ存在せず、これはバグとして複数回提出されています。2つの続きがあります:

- トラッカーがすでに正規名を使っているなら、マッピングは恒等表であり、設定するものは何もありません。それが意図された一般的なケースであり、欠けているステップではありません。
- [wayfinder](https://aihero.dev/skills-wayfinder) の `wayfinder:map` と `wayfinder:<type>` ラベルもここでは作成されず、`gh issue create --label <missing>` はラベルを作成する代わりに完全に失敗します。GitHub リポジトリでの最初の wayfinder 実行の前に手で作成してください。

**ここで他のスキルの振る舞いを設定できますか — [grilling](https://www.aihero.dev/ai-coding-dictionary/grilling) のペース、質問形式、トーン?**

いいえ。3つのことを設定します: トラッカー、ラベル、ドキュメントレイアウト。ユーザーごとの好みの家にする直接のリクエストがありましたが、定着した答えはスキルは意見を持つままであるということです: *「Config is death.」* 好みはすべてのスキルがすでに読む `CLAUDE.md` の平易な指示に属します。

**設定をすべてのリポジトリにコミットする代わりに `~/.claude` に保持できますか?**

今日はできません。多くのリポジトリでスキルを実行している誰かからのまさにこれのオープンリクエストがあり、ユーザーレベルモードは存在しません。すべてのリポジトリが自分の `docs/agents/` を持ちます。

**他のスキルを設定するスキルがあるのは変じゃない?**

1つの長年の不満がイエスと言い、これらの言葉で:*「他のスキルをセットアップするスキルを持つことは私には正しく感じられない — それは LLM が自分のスキルを設定していることを意味する。」* トレードは現実で認識されています: セットアップステップの代替は、イシューに触れるすべてのスキルにトラッカー指示を複製することです。出力は検査可能で編集可能な markdown であり、それが緩和策です — 書かれたすべてのファイルを読み、手で変更でき、日常の微調整はまさにそれであって、別の実行ではありません。

## うまく機能しているなら

- `docs/agents/issue-tracker.md` と `docs/agents/domain.md` が存在し、`triage` がインストールされていれば `triage-labels.md` も。
- `## Agent skills` セクションがあなたのハーネスが実際に読む指示ファイルに現れ、それらの各ファイルを指す1行のサマリー付き。
- 提案されたトラッカーがあなたが実際に使うリモートに一致し、ラベル文字列がトラッカーに実際に存在するラベルに一致する。
- その後、`/to-tickets` がイシューがどこに住むか尋ねずに公開し、`/triage` が発明する代わりにラベルを適用する。
- スキルファイル自体は何も変わっていない。セットアップが `SKILL.md` を編集したなら、何かが間違っていた。

## どこに位置づくか

`setup-matt-pocock-skills` はエンジニアリングフローの**一度だけのセットアップ**であり、チェーンのステップではなく他のすべてが前提とする前提条件です。隣人は読者です: ここに書かれたラベル語彙を適用する [triage](https://aihero.dev/skills-triage)、ここで名付けられたトラッカーに公開する [to-spec](https://aihero.dev/skills-to-spec) と [to-tickets](https://aihero.dev/skills-to-tickets)、マップと子[チケット](https://www.aihero.dev/ai-coding-dictionary/ticket)がどう保存されるかを知るために同じトラッカーファイルの「Wayfinding operations」セクションを読む [wayfinder](https://aihero.dev/skills-wayfinder) です。それが記録するドキュメントレイアウトは、[domain-modeling](https://aihero.dev/skills-domain-modeling) が後で埋めるものです — それは `CONTEXT.md` と ADR を遅延作成し、用語や決定が実際に解決されたときなので、セットアップ後の空のリポジトリが期待される状態です。次にどのスキルを手に取るかは、[ask-matt](https://aihero.dev/skills-ask-matt) がセット全体をルーティングします。
