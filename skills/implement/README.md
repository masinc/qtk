## 何をするスキルか

`implement` は、すでに決定された作業を構築します。[チケット](https://www.aihero.dev/ai-coding-dictionary/ticket)、[仕様](https://www.aihero.dev/ai-coding-dictionary/spec)、または会話で合意したばかりの計画を指すと、コードを書き、シームで [tdd](https://aihero.dev/skills-tdd) を駆動し、進めながら型チェックし、最後に [code-review](https://aihero.dev/skills-code-review) を実行し、現在のブランチにコミットします。

計画を再び開くことは決してありません。インタビューも、明確化のラウンドも、別のアプローチの提案もありません。上流で確定したものは何でも入力であり、スキルの仕事はそれをコミットに変えることだけです。それが、新しい[エージェント](https://www.aihero.dev/ai-coding-dictionary/agent)に「これを構築して」と入力することと区別する点です。後者は喜んで構築しながら作業を再設計します。

## いつ使うか

`/implement` と入力して起動します — エージェントは自分からは使いません。`disable-model-invocation: true` で出荷されるので、他のスキルも呼び出せません。[ask-matt](https://aihero.dev/skills-ask-matt) や [to-tickets](https://aihero.dev/skills-to-tickets) が「それからチケットごとに `/implement`」と言うところはどこでも、それはあなたへの指示であり、エージェントが促されずにやることではありません。

作業が現在どこにあるかが、これが正しいスキルかどうかを決めます:

| 作業は… | 使うもの |
| --- | --- |
| トラッカー上のチケット | `/implement #42`。チケットごとに1[セッション](https://www.aihero.dev/ai-coding-dictionary/session)、チケット間で[コンテキストをクリア](https://www.aihero.dev/ai-coding-dictionary/clearing) |
| まだ分割されていない仕様で、ビルドがセッションにまたがる | まず [to-tickets](https://aihero.dev/skills-to-tickets)、それからチケットごとに `/implement` |
| 仕様で、ビルドが小さい | 仕様に対して直接 `/implement` |
| ちょうど終えた会話にのみ存在し、まだ小さい | 同じウィンドウでその場で `/implement` |
| まだどこにも書き下ろされていない | [grill-with-docs](https://aihero.dev/skills-grill-with-docs)。コードベースがなければ [grill-me](https://aihero.dev/skills-grill-me) |
| 仕様なしでテストファーストにしたい1つの具体的な振る舞い | 直接 [tdd](https://aihero.dev/skills-tdd) |
| すでに構築済みで、チェックしたい | 直接 [code-review](https://aihero.dev/skills-code-review) |

同じセッションのケースは、スキル自身の最初の行がそれをカバーしないので、名前を付ける価値があります。`SKILL.md` は「仕様またはチケット」と言い、それが[モデル](https://www.aihero.dev/ai-coding-dictionary/model)を存在しないファイルの狩りに誘導します。計画がスレッドにのみ存在するなら、起動するときにそう言ってください。

## 前提条件

`implement` はあなたがいるブランチにコミットします。ブランチを作成せず、尋ねもしません。開始する前に、作業を載せたいブランチにいることを確認してください。

チケットが [to-tickets](https://aihero.dev/skills-to-tickets) から来た場合、それらが載っているトラッカーは [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills) によって設定されました。`code-review` は同じ設定を読み、クローズ時に発端の仕様を見つけます。

## 1回の実行がすること

実行は順に5つのビートです:

1. チケットまたは仕様を読み、シームを割り出す。
2. 事前に合意されたシームで [tdd](https://aihero.dev/skills-tdd) を駆動し、一度に1つの red-green スライス。
3. 頻繁に型チェックし、進めながら単一のテストファイルを実行。
4. 最後にテストスイート全体を一度実行。
5. [code-review](https://aihero.dev/skills-code-review) を実行し、それから現在のブランチにコミット。

1回の実行は1つのチケットをカバーします。[to-tickets](https://aihero.dev/skills-to-tickets) が生成するチケットは、単一の新しい[コンテキストウィンドウ](https://www.aihero.dev/ai-coding-dictionary/context-window)に収まるサイズのトレーサーバレット垂直スライスなので、意図されたリズムは: コンテキストをクリア、1チケット実装、コミット、再びクリア。各チケットは自己完結しており、それが前のチケットのコンテキストを使い捨てにできる理由です。

## 事前に合意されたシーム

スキルが動くアイデアは**シーム**です: 内部に踏み込まずに振る舞いを観察する公開境界。テストはシームに生きます。コードが書かれる前に合意されたシームで作業することがテストを耐久性のあるものに保ちます。なぜなら、下の実装はテストが動かなくても書き直せるからです。

「事前に合意された」という言葉は実際の仕事をしており、またスキルの最も弱い関節でもあります。`implement` の中の何もシームを合意しません。`tdd` が尋ねるスキルであり、未確認のシームではテストを書くことを拒否します。実際には、合意は仕様の上流で、または実行の最初のやり取りで起こります。どこでも起こらなければ、前提条件は発火せず、実行は静かに「ただコードを書く」になります。仕様でシームを名指しすることがそれを止めます。

## よくある質問

**終わったが、チケットはまだオープンで、受け入れ基準はまだチェックされていない。**

正しく、期待どおりです。`implement` には完了ステップがありません。コミットで終わり、作業項目には決して触れません。GitHub Issues とローカルマークダウントラッカーの両方で確認されているので、トラッカー統合の問題ではありません。また、`code-review` が生成した指摘に行動せず、発端のイシューの `- [ ]` ボックスにもチェックを入れません。チケットを閉じて、基準を自分で調整してください。これは依存チェーンで最も強く噛みつきます。なぜなら `to-tickets` はフロンティアを、ブロッカーがすべて閉じたチケットと定義するからです。何も閉じられなければ、何も可視的にブロック解除されません。

**全部のチケットを一度に向けられますか、またはいくつか並列で実行できますか?**

いいえ。1回の呼び出し、1つのチケット。チケットキューへのバッチディスパッチと[サブエージェント](https://www.aihero.dev/ai-coding-dictionary/subagent)ファンアウトはどちらも繰り返し要求されていますが、どちらも存在しません。1つのチェックアウトで複数の `/implement` セッションを並べて実行するのは、サポート外より悪いです: 1つのフィールドレポートは、1つのセッションの `git commit --amend` が別のセッションのコミットに着地し、スタッシュが `refs/stash` から消え、コミットが間違ったブランチに着地することを、1つの午後に3つのイシューにまたがって記述しています。セッションは1つの作業ディレクトリ、1つのインデックス、1つの HEAD を共有します。Git worktree がコミュニティの回避策であり、`refs/stash` も worktree 間で共有されることに注意してください。worktree だけではスタッシュのケースは直りません。今日並列性が欲しいなら、自分で組み立てています。

**コミットの代わりにプルリクエストを開けますか?**

組み込まれていません。現在のブランチに直接コミットします。それは何人かにとって熱心すぎます: コードは彼らが動作を検証する機会を得る前に着地します。設定フラグも PR モードもありません。人々は呼び出しでオーバーライドします(「ブランチにコミットして PR を開け」)か、スキルのローカルコピーを編集します。

**`code-review` が変更を見えないと言う。**

`code-review` は `git diff <fixed-point>...HEAD` をレビューし、ステージングと作業ツリーの変更を除外します。`implement` はコミットの前にそれを実行するので、途中コミットがすでに存在しない限り、その差分にはレビューするものがありません。複数の人がこれを報告しており、両側で未修正です。先にコミットし、それから分岐した点に対してレビューしてください。

別途、一部の人は実行内のレビューをまったく望みません。自分が書いたばかりのコードをレビューするエージェントは自分の解決策に偏るからです。新鮮なセッションで固定点に対して [code-review](https://aihero.dev/skills-code-review) を実行するのは正当な代替であり、そのスキルが2つの軸を別々のサブエージェントで実行する理由でもあります。

**1つのチケットが15万トークン燃やした。間違って使っている?**

おそらくスキルの誤用ではなく、チケットが大きすぎます。1回の実行はコードベース探索、シームごとの red-green ループ、スイート全体、レビューを行うので、重要でないチケットが10万[トークン](https://www.aihero.dev/ai-coding-dictionary/token)を超えるのは、何かが壊れた兆候ではなく普通です。てこは上流にあります: [to-tickets](https://aihero.dev/skills-to-tickets) でチケットを正しくサイズ調整し、それぞれが1つの新しいウィンドウに収まるようにしてください。単一のチケットが吹き出し続けるなら、[努力](https://www.aihero.dev/ai-coding-dictionary/effort)レベルを上げるのではなく分割してください。

**新しいセッションでの `/implement #2` が完全に無関係なものに取り組んだ。**

`#2` はエージェントが見える番号付きリストに対して解決されます。新しいセッションでは、設定されたトラッカーではなく、todo ファイル、チェックリスト、または別の作業リストかもしれない。解決は失敗時クローズではなく自信を持って行われるので、間違いは開始されるまで明白ではありません。完全な参照、イシュー URL または `owner/repo#2` を渡し、始める前にタイトルを確認するよう求めてください。

## うまく機能しているなら

- セッションが何を作るかあなたに尋ねるのではなく、チケットまたは仕様を読んで、構築するものを言い直して開く。
- トレースに実際の `/tdd` 呼び出しが見える。差分にテストが現れるだけではない。
- 実行中に型チェックと単一テストファイルが繰り返し実行され、スイート全体が終わり近くで一度実行される。
- あなたが続けるよう促さなくても、実行が現在のブランチのコミットに到達する。
- 差分が1チケット分の変更: すべての層を通る垂直スライスであり、いくつかのチケットを一緒に掃き集めたものではない。

## どこに位置づくか

`implement` はメインチェーンのビルドステップで、最後から2番目です:

```txt
grill-with-docs → to-spec → to-tickets → implement → code-review
```

隣人は、それが消費するチケットを生成し、順序を決めるブロッキングエッジを宣言する [to-tickets](https://aihero.dev/skills-to-tickets)、各シームで内部的に駆動する [tdd](https://aihero.dev/skills-tdd)、コミット前に実行する [code-review](https://aihero.dev/skills-code-review) です。計画スキルの下流に座り、それらを信頼します。渡されたものの形を再検証しないので、構造の悪い地図や水平レイヤーのチケットは書かれたとおりに構築されます。

その信頼が、[wayfinder](https://aihero.dev/skills-wayfinder) が地図を `implement` に直接ループするのではなく [to-spec](https://aihero.dev/skills-to-spec) でチェーンに合流する理由です。作業が本当に小さいことが判明した場合にのみ、地図から直接 `implement` に行ってください。

どのフローにいるか分からないとき、[ask-matt](https://aihero.dev/skills-ask-matt) がセット全体のルーターです。
